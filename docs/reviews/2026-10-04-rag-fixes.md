# RAG 第一轮修复说明（2026-10-04）

本轮落实审查报告中的核心正确性修复，并补数据库迁移、版本检查和真实 SQL 测试入口。知识业务模块、任务队列、Agent 工具与 Wails/Vue 接入仍按后续阶段推进。真实 PostgreSQL 集成测试尚未执行，不能将后端基线视为已经验收。

## 已完成的修复

| 问题 | 修复后的行为 | 主要代码 |
|---|---|---|
| Synthetic 表头污染 child 坐标 | Child 从完整 Markdown 的 parent source range 切分；继承的表头是额外内容，不推进 source offset | `chunker/parent_child.go` |
| 无分隔符长文本超过 token 目标 | 对所有策略结果做最终近似目标切分；继承表头与 breadcrumb 后再次检查，保留 source range 和全文覆盖 | `chunker/budget.go` |
| 标题、breadcrumb 或整批 embedding 超预算 | 完整 SearchContent 在任何远程请求前统一预检；单条和整批分别限额；超限返回错误，不截断原文 | `embeddinginput/budget.go`、`indexer/postgres/ingestion.go` |
| 去重前截断导致少返回上下文 | Pipeline 保留重排后的候选池，在 parent 扩展/合并之后应用 FinalTopK，并汇总 child evidence | `search/pipeline.go`、`rerank/reranker.go` |
| 零值配置被静默替换 | overlap、检索阈值、单通道 RRF 权重、rerank 浮点参数的显式 0 保留；负数、非 finite、越界和非法模式提前失败 | 各模块 `validation.go`、`rag.go` |
| 同维度不同模型混用 | collection 持久化 profile，包含 endpoint、model/revision、维度与 SearchContent 表示；密钥和请求超时不参与身份 | `embeddinginput/profile.go`、`indexer/postgres/profile.go` |
| 旧任务覆盖新版本或恢复已删除文档 | 解析前领取 attempt；事务锁定并校验最新 head 后才删除旧 chunks；取消/删除推进 head，删除保留 tombstone | `indexer/postgres/revisions.go`、`ingestion.go` |
| 同一 attempt 改写引用内容 | 同 attempt 只允许 Markdown、处理配置和完整索引输入快照一致的重试；标题、breadcrumb、chunk 集合变化也会拒绝覆盖 | `indexer/postgres/snapshot.go` |
| 更新中读到旧 child 与新 parent | 结果携带 collection/document revision；RRF 身份包括 revision；parent revision 不匹配时保留原 child 并记录诊断 | `retrieval/result.go`、`retriever/postgres/revision.go` |
| Parser 同步且缺少边界 | 共享独立 worker，支持取消/超时、文件/输出/ZIP 展开限额和 warning 返回；先复制临时快照再解析 | `internal/documentparse` |
| 文本格式缺失 | 支持 UTF-8/BOM 的 MD/TXT/CSV，CSV 首版保留原始文本 | `loader/tabula/loader.go` |
| Hybrid 任意通道失败即失败 | 默认 strict，可显式 allow_partial；失效通道的部分 rows 不参与融合，降级有诊断，取消传播；总 deadline 不等待未响应通道 | `retriever/postgres/retriever.go` |
| 外层不能选检索模式 | SearchRequest 增加 hybrid/semantic/keyword 和 Limit；legacy factory 对不支持的选项明确报错 | `application/service.go`、`pipeline_factory.go` |
| 两条入库路径契约混淆 | 正式版本化入口走 Ingest/ReplaceDocument；Eino Store 只接受包含完整 source envelope 的整文档 flat chunks，拒绝局部分批和 parent-child | `transformer/chunker/transformer.go`、`indexer/postgres/indexer.go` |
| Schema 无版本与错误 parent FK | 引入版本、checksum、事务迁移锁、已知旧 schema 升级；parent 删除只清空 parent_chunk_id，保留 collection_id | `indexer/postgres/migrations.go`、`schema.go` |

## 调用变化

`rag.DefaultConfig().EnsureSchema` 改为 `false`。先使用迁移账号设置 `HUMBERT_RAG_DATABASE_URL` 并执行：

```sh
go run ./cmd/rag-migrate
```

当前 SQL 的最低兼容门槛是 PostgreSQL 15+、pgvector 0.7.0+、pg_search 0.25.0+，分别对应列级 SET NULL、halfvec 和 paradedb access method。门槛检查不替代固定版本组合的集成测试。参考 [PostgreSQL 约束文档](https://www.postgresql.org/docs/17/ddl-constraints.html)、[pgvector 文档](https://github.com/pgvector/pgvector)、[ParadeDB 建索引文档](https://www.paradedb.com/docs/reference/indexing/create-index)。

正式导入需要稳定的业务 DocumentID，路径变化或重新解析沿用该 ID：

```go
result, err := engine.Ingest(ctx, application.IngestRequest{
    CollectionID: "manuals",
    DocumentID: "manual-001",
    Source: document.Source{URI: "/data/manual.md"},
    Splitter: chunker.DefaultConfig(),
    ParentChild: true,
})
```

Attempt=0 在解析前自动预留新 attempt。未来 job worker 可先调用 `ReserveDocument`，把返回值保存到 job，再通过 IngestRequest.Attempt 提交。`CancelDocument` 使未完成任务失效，保留已发布数据；`DeleteDocument` 原子删除已发布数据并阻止旧任务恢复内容。失败任务的重试领取新 attempt；同 attempt 的相同输入重试保持幂等。

profile 一旦绑定，改变模型、endpoint、模型 revision 或 SearchContent 表示会返回 mismatch；应在新 collection 重建并切换业务绑定。历史向量没有可信 profile 时返回 ErrUnboundLegacyIndex，迁移保留数据但不自动猜测模型。模型别名指向的权重发生变化时，调用方应更新 ModelRevision。

`Embedding.InputBudget` 是 NewRAG 的唯一预算入口，同时用于入库和查询；standalone Indexer 可单独设置自己的 InputBudget。默认 byte 计数对 byte-based tokenizer 提供保守估计，支持注入实际 tokenizer。8192/65536 是本地保护默认值，需要按模型供应商调整。分块 TokenLimit 是近似目标，header 自身超过该目标时保留内容，最终由 provider budget 决定是否允许；不会为了满足目标丢弃引用内容。

配置默认值从各模块 `DefaultConfig()` 获取。空 Strategy 继续使用 legacy；`ChunkOverlap=0` 关闭重叠，base overlap=0 也关闭 parent/child overlap。空 RRF struct 整体用默认值；其余配置保留 K=0 和单通道权重 0。TopK=0/资源限额=0 仍表示默认值，具体语义见 README。

完整用法已更新到 [RAG README](../../internal/rag/README.md)。

## 验证结果

在本机隔离 Go 构建缓存并去除已有 GOROOT 环境变量后：

- `go test -count=1 ./...` 全部通过，包括 App、Runtime、Services 和共享解析器的现有回归；macOS 链接器输出了 deployment target 警告，测试未失败。
- `go test -count=1 ./internal/rag/... ./internal/documentparse ./internal/documenttext ./cmd/rag-migrate` 通过。
- `go vet ./internal/rag/... ./internal/documentparse ./internal/documenttext ./cmd/rag-migrate` 通过。
- 对 application、chunker、embeddinginput、indexer/postgres、retrieval、retriever/postgres、search、rerank 执行 `go test -race -count=1` 通过。
- 确定性审查复现已恢复预期行为，修复前后输出保存在 [复现说明](2026-10-04-rag-probes/README.md)。

真实 SQL 测试入口位于 `internal/rag/indexer/postgres/integration_test.go`，覆盖新库与已知旧库迁移、重复迁移、flat/parent-child、BM25/dense/hybrid、collection 隔离、禁用过滤、并发 attempt 预留/提交、同 attempt 输入一致性、更新/取消/删除的 attempt fence、profile mismatch、单独删除 parent，以及 SQL/embedding 失败后的原版本保留。模型使用确定性非零向量，验证 SQL 与生命周期，不评价真实模型质量。

当前没有提供符合条件的独立测试库，本机 PostgreSQL/扩展基线较旧，故集成测试为 **SKIP，尚未实测**。测试需要已安装扩展的独立库；不会自动创建扩展，只创建并清理自己的随机 schema：

```sh
# 在外部安全设置 HUMBERT_RAG_TEST_DATABASE_URL 后执行
go test -count=1 -v ./internal/rag/indexer/postgres -run '^TestIntegration'
```
