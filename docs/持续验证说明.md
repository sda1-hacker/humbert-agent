# 持续验证

从仓库根目录执行：

```bash
./scripts/verify.sh --checks ../humbert-agent-checks
```

顺序为 Go 后端构建、`go vet ./...`、`git diff --check`、前端生产构建、外部行为回归。任一步失败立即退出。只传 `./scripts/verify.sh` 时仅做构建检查，并明确提示未执行行为回归。脚本可作为本地或已有 CI 的入口，不安装依赖、不读取用户模型配置、不调用付费模型。

外部用例位于仓库旁的 `humbert-agent-checks/`，需要单独保留、备份或版本管理。该目录包含可移植的 `run.py`、Go/Node 用例及固定 RAG/CSS 基准，不依赖本次会话的临时文件。Go 使用临时 overlay 和 race 检查，前端仅替换 IPC 边界，运行真实 Store、投影与组件。执行环境需先安装 Go、Node、Python 3 和前端依赖；知识库网络等待用例需允许监听本机回环随机端口。

外部回归覆盖文件边界与搜索预算、进程取消、Skill 安装更新回滚、知识库连接并发、能力集合校验、Runtime 异步竞态和侧栏搜索/渲染。四种语言的侧栏渲染与原有 CSS 声明均核对；这些检查不等同于真实 WebView 的视觉验收。

真实环境另行核对：

- Wails 启动/关闭、会话切换、侧栏菜单与窄窗口布局。
- 真实模型连续工具调用、审批暂停与恢复、取消和失败后继续；确认副作用不被重复执行。
- 真实 PostgreSQL 初始化、导入/检索/删除、导入取消与失败后重试、重启恢复。
- 浏览器与桌面截图/输入所需的系统授权。

执行记录应区分构建、外部回归和真实环境验收，不能用编译成功替代外部集成已实测。
